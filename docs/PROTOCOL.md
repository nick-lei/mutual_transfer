# 邻传 NearLink：协议与技术边界

本文件记录当前技术设计、协议和后续路线；视觉规范见 [DESIGN.md](../DESIGN.md)，产品定位见 [PRODUCT.md](../PRODUCT.md)。

## 已实现的核心流程

1. 启动本机 HTTP 服务，获取 IPv4 地址，广播设备信息。
2. UDP 组播与广播发现设备；组播被路由器过滤时可输入 IPv4 与端口手动连接。
3. 文件、多文件或文件夹进入发送队列，保留文件夹内的文件路径。也可从系统拖入。
4. 发送端提交元数据；接收端显示来源、文件数量、总大小与文件名，每一批均需明确接收。
5. 接收方同意后返回随机会话令牌与能力列表。支持 `streaming-sha256-v1` 时双方在流式收发期间同步计算 SHA-256，不预读整个文件。
6. 接收端检查大小、令牌和来源地址，写入 `.part` 文件并返回摘要。发送端校验摘要及源文件状态，再提交确认；接收端检查相同摘要后才移动到目标路径。旧版发送方提供预计算摘要，接收端仍在写入期间校验。
7. 同名文件添加编号；失败删除临时文件。发送方可重新发送，取消会终止该发送批次。
8. WebSocket 传递文本，接收端返回 ACK；界面区分发送中、已送达和失败。重试沿用消息 ID，接收端去重。
9. 设备身份、已知设备、设置、最近 300 条文件记录及 1000 条消息保存在本地。重启后的未完成文件标记为中断。

## 技术取舍

| 模块 | 当前选择 | 理由与边界 |
| --- | --- | --- |
| 客户端 | Flutter + Material 3 + Lucide | 原生桌面文件系统访问，统一界面；当前只生成 Windows 平台 |
| 设备发现 | UDP 239.255.77.77:45877 + 广播 | 无额外服务；跨网段、访客 Wi-Fi/AP 隔离不保证可达 |
| 文件传输 | HTTP 流式 PUT | 原生端到端直连、背压与错误处理清晰；不需要 WebRTC 信令或 STUN/TURN |
| 消息 | WebSocket + 应用层 ACK | 低延迟双向会话；ACK 表示送达，不表示已读 |
| 完整性 | SHA-256 + 字节数校验 | 检查文件损坏，不构成身份认证或加密 |
| 存储 | 本地 JSON | MVP 依赖少；更大历史规模应迁移 SQLite |
| 任务调度 | 批内串行，不同批次独立 | 限制单批磁盘争用；尚未实现全局并发调度 |

## 协议

默认 TCP 45878；被占用时选择空闲端口，实际端口显示在界面。客户端手动连接需包含非默认端口。

UDP 接收器监听 `0.0.0.0:45877`，按网卡加入组播组。发送使用每个 IPv4 地址独立的组播、广播 socket，明确指定组播出口，隔离 Windows 1232 等异步路由错误。单个发送通道失败不关闭其他通道；接收器或全部发送通道失效时每 5 秒重新枚举网卡并重建发现服务，用户也可立即重新检测。正常运行时每 30 秒更新网卡。发现恢复会清除警告，不重启 TCP 传输和 WebSocket 服务。UDP 报文格式与 v1 设备兼容；socket 可用不保证路由器、防火墙或另一台设备允许报文到达。

| 接口 | 作用 |
| --- | --- |
| `GET /v1/info` | 产品标识、协议版本、设备 ID、名称、平台和端口 |
| `POST /v1/offers` | 文件元数据协商，等待接收确认（90 秒） |
| `PUT /v1/files/{id}?token=…` | 文件内容；新模式携带 `x-nearlink-integrity: streaming-sha256-v1`，旧模式携带 `x-nearlink-sha256` |
| `POST /v1/files/{id}/commit` | 新模式确认，JSON 包含 `token` 和 `sha256`；检查令牌、原来源地址、待确认状态与摘要 |
| `POST /v1/cancel` | 终止原来源地址创建的批次 |
| `GET /v1/chat` | WebSocket：hello、message、ack |
| `POST /v1/groups` | 群主同步版本化群组名称、成员与解散状态 |
| `POST /v1/groups/leave` | 成员通知群主退出，群主更新并分发名单 |
| `POST /v1/groups/join` | 退出后由群主重新添加的成员，主动确认重新加入 |
| `POST /v1/group-messages` | 成员直接逐人发送群消息；HTTP 200 表示该成员已接收 |

文件路径拒绝绝对路径、`..`、NTFS 备用数据流、Windows 保留设备名和非法字符。接收目录逐级检查，避免通过已存在的目录链接写到保存目录外。

接收请求确认返回 HTTP 200，主动拒收返回 HTTP 409，90 秒未操作返回 HTTP 408。
确认超时属于未完成，不计为主动拒收；旧版接收端可能仍将拒收和超时统一返回 409。

### 流式完整性协商

`GET /v1/info` 及接收成功的 offer 响应增加 `capabilities: ["streaming-sha256-v1"]`。发送方必须从当前 offer 响应确认能力，才能选择新模式，未知能力忽略。老接收端没有该字段时自动预计算 SHA-256，通过原请求头发送；新接收端接受老发送端的请求头。

新模式 PUT 返回 `{"sha256":"…","commitRequired":true}`，此时文件仍为 `.part`，界面处于校验中。提交成功返回相同摘要。未确认文件默认两分钟超时清理；摘要错误、取消和正常退出也会删除临时文件并释放目标路径预留。重复上传和重复提交拒绝，不覆盖现有文件。确认响应丢失时发送方可能显示失败而接收方已完成，重试会作为新传输自动编号。

发送端按 1 MiB 分块读取；接收端按磁盘消费能力施加背压，取消定期强制 flush，避免额外的完整文件复读。Windows 通过系统 CNG 增量 SHA-256 加速，其他平台或初始化失败使用 Dart 算法。旧模式的预校验在独立 isolate 执行。两端以 45 秒无字节进展判断传输停滞；上传完成后的响应与确认仍有各自超时。源文件大小和修改时间变化会使发送失败，这不保证识别所有同大小且保留时间戳的并发修改。

## 后续正式版优先级

1. **TLS 与设备配对**：自签名证书、首次连接校验短码、已配对设备证书指纹固定。当前为明文 HTTP/WebSocket，只适用于可信局域网，不能声称加密传输或可靠识别对端身份。
2. **断点续传与大任务调度**：持久化任务、分块校验、可恢复偏移、全局并发和带宽控制。当前失败重试从头开始，不提供暂停与续传。
3. **完整发现与连接体验**：mDNS/DNS-SD、网卡选择、IPv6、设备配对记录、二维码。当前只支持 IPv4，不兼容 LocalSend 的现有协议。
4. **桌面完成度**：系统通知、自动更新与安装包代码签名。托盘、开机启动、截图、本地诊断日志和可点击安装的 Windows 安装包已实现。
5. **多端扩展**：Android/macOS/iOS/Linux 的权限、存储沙箱和后台生命周期，再进行真实多机网络测试。

## 当前限制

单批最多 1000 个文件；空目录和符号链接不传输。新模式减少完整文件读盘次数，实际速度仍受磁盘、网络和接收设备影响。历史消息在本地以明文 JSON 保存。当前没有账号、云中转、浏览器接收、文件预览、端到端加密或跨网络穿透。

## 设备备注与局域网群组（0.2.0）

备注按设备 ID 保存在本地 `settings.json`，最长 32 字符，清空后使用原设备名。
备注不出现在设备广播、hello、群成员名单或任何网络请求中；设备更新不会覆盖备注。

群组能力标识为 `lan-groups-v1`，协议主版本仍为 1，未知能力可以忽略。
群组上限 32 台设备（含本机），创建和添加新成员需要对方在线且支持该能力。
创建/添加后名单直接同步至成员设备，不另设入群审批；文件仍必须逐人确认。
群组 ID、群主 ID、成员 ID 均使用 32 位十六进制标识，名称最长 32 字符。
`POST /v1/groups` 携带 `peer` 和 `group`，后者含 `id/name/ownerId/revision/members/dissolved`；
成员包含原设备名、IPv4、端口及平台。只有声明身份与已知群主 ID 一致的发送方可以更新；
版本必须递增才覆盖，旧快照不恢复被移除的身份。第三方名单只补充缺失设备，
不覆盖已经观测到的设备地址或本地备注。当前仍沿用可信局域网的声明身份模型，
这些检查不等同于密码学认证。

群主保存待同步成员（包括被移除成员），每 30 秒及手动重试同步；
成员退出先保存本地退出状态，再通知群主。退出状态不会被后续快照自动恢复。
退出后由群主重新添加，再由成员在群组详情主动确认重新加入；加入时向群主核对最新名单。
群主离线时已有成员仍然逐人直连发消息，但名单编辑需要群主在线。
成员离线期间尚未收到的移除/解散状态只能在同步恢复后生效，没有中央在线授权服务器。

群消息包含 `peer/groupId/id/text`。接收方检查本机仍在群中且发送方在本地最新名单内，
按发送方、群组和消息 ID 去重，保存后返回 200。一次最多并发向四名成员发送。
发送方持久化每个原收件人的送达/失败状态；重试沿用 ID，只补发未送达且仍在群内的成员，
不向后来加入的成员补发历史。送达不代表已读；离线消息没有自动补发队列。
群未读使用 `group:<id>` 独立会话键，防止与发送者私聊的未读和草稿混合。

群文件在既有 offer 中增加可选 `groupId`，接收端验证成员身份后仍逐批确认。
最多并发三个接收者，每人有独立令牌、传输记录和结果；失败仍从头重试。
一名成员拒收、超时、连接失败或取消，不会终止其他成员的任务。所有接收方处理结束后，
发送端统一提示完成、拒收、未完成和取消的成员数；只有所有文件都完成的成员计为完成。
群文件页只展示本机参与的群传输记录，后来入群者不能下载历史文件。
最近 1000 条消息和 300 条传输记录仍适用，群组和退出/解散状态独立保存在设置文件中。

验证应区分同机回环测试与真实多机网络：自动测试覆盖前者，真实 Wi-Fi、路由器、防火墙与多网卡场景仍需多机验证。
