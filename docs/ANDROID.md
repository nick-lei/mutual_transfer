# 邻传 Android

Android 8.0（API 26）及以上。版本 `0.3.11+26`，包名
`app.nearlink.mutual_transfer`。沿用现有蓝白、薄荷绿与品牌图标，保留 Windows 端。

## 手机端体验

- **发送**：文件或照片/视频选择、紧凑待发摘要、设备/群组选择，底部明确发送。
  点击摘要展开完整清单，所有已选文件仍可单独移除。
- **消息**：与发送页一致的独立会话卡片、最近消息时间、未读数、独立聊天页、系统返回、草稿、群组。
  长按会话或设备进入备注等操作；输入法换行，图标发送。
  聊天页附件和顶部文件图标可直接多选并发送给当前会话，不跳转发送页；文字草稿与首页待发队列独立保留。
  文件与文字按时间混排，展示文件名、大小、实时进度、速度、等待、完成及失败状态。
  可直接接收或拒绝一批文件、取消传输、失败重发、打开文件，收到的文件还可另存和分享。
  群聊按成员分别展示文件结果。文件卡片与传输记录共用本地数据，清理记录时会同步清除对应卡片。
- **设备**：搜索备注、设备名称与地址；手动 IPv4 连接；文件、消息与备注入口。
- **记录**：沿用原来的逐文件卡片与“全部 / 传输中 / 已接收 / 失败”筛选，
  展示进度、速度、大小和时间；点击文件或更多菜单可打开、另存、分享、重试或取消。
  每个文件直接可见，不折叠为批次。批次标识仅保留为本地元数据，不改变传输协议。
- **设置**：设备名称，以及接收与保存、通知与声音、连接信息、诊断与日志四个入口。
  详细开关在子页配置，保留后台接收与各类通知、提示音的独立设置。
  首页与子页统一使用白色列表项、8 dp 圆角和蓝色/薄荷绿图标底；相关开关分组展示，
  底部品牌与版本信息改为紧凑横排。设备名称整行可点击编辑，长名称支持两行显示。

窄屏用底部导航；宽度至少 840 dp 时改用导航栏和分栏会话。安全区、键盘与系统返回
参与布局。接收请求直接悬浮于当前内容，可收起提醒、重新展开并点开底部详情确认。
消息列表显示最近消息时间，设备页区分在线与离线，并保留备注与原名称。
Windows 标题栏、托盘、
开机自启和全局截图快捷键只在桌面端出现。

## 文件与系统权限

系统选择器选取文件，不申请整个存储空间的访问权限。接收内容先保存到应用内部
`files/Received`。从记录里“另存到手机”会打开 Android 系统保存窗口；“打开”和“分享”
通过 FileProvider 临时授权。**卸载或清除应用数据会删除内部接收文件**，需要长期保留的
内容应先另存。文件选择和其他应用分享进来的文件会暂存在应用缓存中。

收到的 `.apk` 安装包可从聊天或传输记录中点击“打开文件”进入系统安装器。
应用声明 `REQUEST_INSTALL_PACKAGES`；Android 8.0 及以上若尚未允许邻传安装应用，
首次打开 APK 会进入邻传对应的“安装未知应用”系统授权页。用户开启权限并返回后，
邻传重新核对权限和文件，再继续进入安装确认；不开启则显示提示，之后可再次点击重试。
如果系统在授权期间终止了邻传，重新打开应用后需要再次点击该安装包。
接收或分享 APK 不会自动安装，也不会静默安装。厂商安装器的确认、安全检查、签名和
版本校验仍由系统决定。普通文件的打开、另存与分享方式不受此流程影响。

在相册、文件管理器或浏览器中选择“分享 → 邻传”会暂存文件/文字，由用户选择设备后
点击发送，不会自动转发。单批最多 1000 个文件，原有传输协议、完整性校验、备注与
局域网群组复用。所有通信仍需局域网可达；协议没有新增加密、云中转或断点续传。

## 通知与后台

Android 13 及以上需要通知权限。用户在设置中点击开启或打开后台接收时才请求权限。
文件请求、消息、传输完成使用各自通知频道；通知点击打开匹配的请求、会话或记录。
文件请求还提供接收/拒绝操作。具体声音及显示效果同时受系统频道、音量与免打扰控制。

后台接收默认关闭。开启后运行 `connectedDevice` 前台服务，显示可停止的常驻通知。
发现设备持有组播锁；服务中的实际文件传输使用有时限的唤醒锁。没有开机自启或
自动重启服务。厂商省电策略、强行停止、断网和系统终止进程仍会中断连接；需要持续
接收时，请在手机系统中允许邻传后台运行。关闭后台接收后不承诺离开应用仍能接收。

## 构建

安装 Flutter 3.44 / Dart 3.12、JDK 21、Android SDK 36 / Build Tools 36.0.0。
项目 Android Gradle Wrapper 固定 9.1.0，并验证官方 SHA-256。
当前 Flutter 插件组合使用 AGP 9 的旧版 Kotlin 接入方式；项目构建配置为
`file_picker 11` 补充其遗漏的 Kotlin 插件，且关闭 Kotlin 增量缓存，避免 Windows
项目与 Pub 缓存分处不同盘符时失败。无需修改全局 Pub 缓存中的依赖源码。

当前 Windows 开发机可用以下脚本在项目 `build/android-tools` 内准备工具链：

```powershell
.\tool\prepare_android.ps1
.\tool\build_android.ps1
```

可选 `prepare_android.ps1 -WithEmulator` 下载 Android 35 Google APIs x86_64 镜像。
工具目录不属于发布内容。脚本的环境变量仅对当前脚本进程生效。
本机若需要代理，先在调用脚本的 shell 配置 `JAVA_TOOL_OPTIONS` 的 HTTP/HTTPS
代理；不要把本机代理地址提交到 Gradle 配置中。

使用自备 SDK/JDK 的标准构建方式：

```powershell
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
flutter build apk --release
```

脚本产物为 `outputs/NearLink-0.3.11-android-preview.apk`，使用本机开发证书签名，
用于直接安装试用。正式发布前需要配置持久化私有签名和备份；不同开发机生成的
开发证书可能不一致，不能据此承诺跨机器构建覆盖升级。不要把签名私钥放进仓库。

## 模拟器联调

当前选择雷电 14，官方完整安装包为
`https://lddl01.ldmnq.com/download/leidian14/ldinst_14.0.34.1.exe`。
本机已下载至 `build/emulator-tools/ldinst_14.0.34.1.exe`，Authenticode 签名有效。
雷电已安装到 `D:/leidian/LDPlayer14`，实例 0 运行 Android 14。安卓显示覆盖为
1080×1920、420 dpi，以验证手机竖屏。预览 APK 已安装并运行。
使用 `build/android-tools/sdk/platform-tools/adb.exe` 连接 `127.0.0.1:5555`。
原生截图、通知与双向传输结果见 `.impeccable/review/android-verification.md`。

`tool/verify_android_peer.dart` 提供独立的传输验证端，不使用 Windows 邻传的配置、
历史或接收目录，也不广播发现其他设备。使用明确指定的安卓端地址配对，然后发送
生成的消息和三个文件（空文件、文本、8 MiB 二进制文件）。只自动接收该配对设备
发回的文件，结果和接收文件保存在 `build/android-verification/peer-*`。

```powershell
dart run tool/verify_android_peer.dart --self-test
dart run tool/verify_android_peer.dart 192.168.1.123:45878 180
```

第二条命令中的地址必须替换为实际安卓测试设备的可达地址。它先等待安卓端确认
接收，再最多等待 180 秒回传。收到回复消息与三个原名测试文件后自动结束，
`result.json` 记录消息状态、文件状态与接收 SHA-256。缺少回传消息、缺少文件、
传输失败或校验不一致都会返回失败退出码。`--self-test` 使用两个本机服务验证
该工具，不能作为安卓运行证据。模拟器 NAT 下需要分别记录手动连接、ADB 隧道和
UDP 自动发现的结果；隧道连通不代表局域网发现通过。

本次验证 Windows → Android 使用临时 ADB 转发，Android → Windows 使用手动连接
主机局域网地址。三个文件均完成回传且 SHA-256 一致。手动连接会保留输入的地址和
端口，收到对端握手后也不会被其内部端口覆盖。验证结束后临时 ADB 转发已删除，
后台接收已通过常驻通知的停止操作关闭。真机自动发现与厂商后台省电策略仍需另测。

## 0.3.1 连接修复

文件发送、新建消息连接和群组请求在发送前核对对端设备 ID，防止模拟器 NAT、失效的
历史地址或端口复用把请求发给错误设备。广播和入站握手不再把已有返回地址改为本机
监听地址。Android 自定义名称也会在重启后保留。模拟器使用 NAT 时仍需要桥接或端口
转发才能从局域网访问；内部 IP 不等同于局域网可达 IP。详见
`docs/NETWORK_TROUBLESHOOTING.md`。
