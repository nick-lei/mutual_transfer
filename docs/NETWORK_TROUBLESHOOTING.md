# 自动发现与 Windows 1232

## 0.1.1 修复

Windows 错误码 `1232` 表示网络位置不可达。它出现在 UDP socket 的异步错误中，单凭该日志不能确定是哪个网卡、出口或网络策略造成，也不能说明 TCP 文件和消息服务已失效。

0.1.0 将任意 UDP 异步错误标成永久的自动发现故障，重试仅重新发送报文，既不重建 socket，也不清除故障状态。同时顶部与侧边栏只判断 HTTP 服务是否启动，可能继续显示局域网就绪或设备可被发现。

0.1.1 的处理：

- 接收与发送分开；各个 IPv4 网卡分别创建组播、广播发送 socket。组播通过 `IP_MULTICAST_IF` 明确指定出口。
- 一个发送通道失败不会关闭其他通道，异步错误记录对应的网卡、源 IP、目标 IP 与系统错误码。
- 接收器或全部发送通道失败后，每 5 秒重新检测网卡并重建发现服务；提示右侧的刷新图标可立即重试。
- 正常运行时每 30 秒重新检测网卡，适应网络切换。重新检测不重启 TCP 和 WebSocket 服务。
- 全部不可用时顶部显示“需手动连接”，侧边栏显示“可通过 IP 连接”；提示栏提供连接与重新检测的图标操作。恢复后警告消失。

UDP 格式和发现端口 `45877` 保持兼容。发送 socket 可用仅表示本机具备发送条件，无法证明防火墙、路由器或对端已放行报文。

## 现场排查

1. 两台设备都打开邻传，确认连接同一可互通局域网。
2. 等待自动重试，或点击警告右侧的重新检测图标。
3. 仍失败时，从“设置 → 运行日志”查看 `discovery` 事件。新日志可区分具体网卡和组播、广播目标。
4. 可通过对端“设置 → 连接信息”中的 IPv4 地址和端口手动连接。若 IP 连接也失败，应继续检查对端是否在线、所用网络的应用通信规则以及路由器的 AP/访客隔离；手动连接不能绕过这些网络限制。

## 模拟器 NAT 与“不能向自己发送文件”

模拟器的 Android 内部地址不一定是局域网设备可直接访问的地址。例如，本机雷电的
Android 地址为 `172.16.1.15`，经 NAT 发送到局域网的 UDP 报文来源却是宿主机地址。
如果再把 Android 声明的默认 TCP 端口与宿主机 IP 拼接，可能正好连接到宿主机的邻传。
此时旧版接收端会返回“不能向自己发送文件”。设备 ID 并未因此合并，错误来自返回地址。

0.3.1 的处理：

- 广播或入站握手中指向本机 HTTP 监听端口的地址，不再覆盖已有的有效返回地址。
  只有这种地址的新设备不会被标为可发送的在线设备。
- 文件发送、新建消息连接和群组 HTTP 请求先查询 `/v1/info`，核对实际设备 ID。
  指向本机或另一设备的连接会被阻止，并记录 `peer_endpoint_mismatch`。
- 文件批次在确认后固定使用已核对的地址，后续广播不会改变上传与取消的目标。
- Android 用户设置的设备名称在重启后保留，可为模拟器单独命名以区别真实手机。

这不提供 NAT 穿透。若需要其他局域网电脑直接访问模拟器，请在模拟器网络设置中使用
可用的桥接网络，或配置端口转发，然后通过转发后的 IPv4 和端口手动连接。普通同一
局域网的真实手机使用手机自己的地址，不使用模拟器内部地址。型号或名称可能相同，
区分设备应以设备 ID 及经过核对的连接端点为准。
