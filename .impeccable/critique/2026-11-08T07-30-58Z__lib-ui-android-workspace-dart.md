# 邻传 Android 手机布局与样式评审

本次目标是检查现有手机界面还可以细化的地方。保留蓝白与薄荷绿主题、品牌 N 图标、Lucide 图标和快速发送优先的产品方向。未修改界面或业务代码。

## 证据与边界

- 已检查 Android 14 雷电模拟器的发送、消息列表、聊天、设备、记录、设置和接收提醒原生截图，并对照当前 Flutter 源码。
- 本轮重新截取首页默认字号、1.3 倍字号和系统深色模式。系统深色模式下应用首页仍为浅色；1.3 倍字号首页未见裁切，但空状态说明将 Wi-Fi 拆行，主要操作接近底栏。
- android-widget-staged.png 和 android-widget-small-large-type.png 是 Flutter widget 布局预览，只用于辅助检查待发和小屏边界，不作为 Android 原生运行证据。
- 软键盘弹出后的空间、真机手势安全区、TalkBack、深色方案和长时间后台行为不属于已完成的实机验证。

## 设计针对性

品牌标识、附近设备、直接发送与收件确认符合邻传的使用场景，整体身份明确。主要不足在于手机页面仍共享部分桌面容器与间距：消息页大白色圆角外壳、聊天顶部区域、逐文件传输卡片、展开过长的设置页。年轻化应体现在更清晰的重点、轻盈的表面和及时反馈。

自动网页检测器：not applicable (native platform)。本次使用原生截图与源码评审。

## 当前值得保留的部分

1. 品牌 N、蓝色操作、绿色在线/成功的识别体系，能延续桌面和手机的产品身份。
2. 发送、消息、设备、记录、设置五个目的地明确，底部图标配短标签适合手机识别。
3. 底部发送确认区、接收确认面板和至少 48dp 的主要触控目标，提供了可继续完善的交互基础。

## 优先问题

### P1：首页内容顺序削弱快速发送

位置：lib/ui/android_workspace.dart:252、298、349、513。

当前两个文件入口、分区间距与大空状态占据较多首屏空间。选文件后，最多八条清单插在“发送给”之前，收件人会随文件增加下移。用户选择内容后最需要确认目标，却必须向下查找。

建议：将文件入口收紧至约 88–96dp；把已选内容默认收成“缩略图/文件图标 + 数量 + 总大小”的摘要，点击展开已有管理面板。在线设备和收件人留在主要视野内，底部确认区持续显示“发给谁、发什么、发送”。空状态缩短，让手动连接入口更容易找到。大字号允许入口随内容增高，不固定裁切。

对应：$impeccable adapt、$impeccable layout。

### P2：消息与聊天存在桌面容器痕迹

位置：lib/ui/workspace.dart:2139、2264、2411、2489。

消息页的“消息”标题下面再次显示“会话”，并被一个几乎覆盖全屏的白色圆角容器包住。会话行没有最近消息时间。聊天每条消息分别显示时间和送达信息，底部还有 20dp 间距，连续短消息的密度偏低。编辑框焦点描边较重。

建议：手机消息页改为直接铺开的会话列表，去掉重复标题和大外壳。行内使用头像、备注、预览，右侧对齐时间和未读数。聊天使用标准顶部栏；相邻同一发送者消息收紧间距，时间间隔较大时再显示时间分隔，发送中与失败保留醒目反馈。输入区使用浅色填充与较轻但清晰的焦点边框。软键盘适配要在真机补验，不能将当前未观察到的遮挡当作已存在缺陷。

对应：$impeccable adapt、$impeccable typeset。

### P2：传输记录重复信息多，筛选维度混合

位置：lib/ui/android_workspace.dart:677、734。

同一批三个文件显示为三张完整卡片，重复设备名与时间。当前“全部 / 传输中 / 已接收 / 失败”混合了方向与状态，没有对称的已发送方向入口。

建议：以传输批次汇总设备、方向、文件数、总大小和成功数量，点击展开逐文件详情。传输中单独置顶并显示总进度与速度；历史使用更紧凑行。方向采用“全部 / 发送 / 接收”，状态通过筛选图标单独选择，避免在一组中混合概念。收到的文件将“打开”与“另存到手机”放到易到达的位置；不能新增当前服务不支持的暂停/断点续传承诺。

对应：$impeccable layout、$impeccable clarify。

### P2：设置页一次暴露过多开关

位置：lib/ui/android_workspace.dart:1009、1065、1132。

当前设备身份区、后台说明和多组通知/提示音开关占据长页，连接诊断位于更下方。初次用户难判断最常用的选项，熟练用户也要反复滚动。

建议：主设置保留设备名称、“接收与保存”、“通知与声音”、“连接与诊断”等摘要入口。独立开关放入对应子页，继续保留现有配置能力。后台接收保留简短行为说明；电池限制等详细解释按需展开。应用内文件存储和卸载风险应放在接收与保存页，并在另存操作附近提供清楚反馈。

对应：$impeccable distill、$impeccable layout。

### P2：设备身份与网络信息的优先级可完善

位置：lib/ui/android_workspace.dart:252、471、580。

首页优先显示原始型号；设备页以同样的平台图标表示多台电脑，备注后的原设备名要进入操作面板才看到。设备增多时，名字和状态更需要帮助用户确认接收对象。本机 IP 地址又占据设备页较显著的区域。

建议：显示备注为主标题，原设备名/系统为次级身份；在线与最近离线分组。地址移入简洁的“本机连接信息”入口并保留复制操作。最近使用设备可以优先排序，但除非有真实用户分类，不标记“我的设备”。保留长按修改备注入口，并在点击后的操作面板中明确展示。

对应：$impeccable clarify、$impeccable layout。

## 用户视角与认知负担

- 单手互传用户：选完几个文件后，设备被清单推远；底部确认区是正确方向，应与内容摘要共同工作。
- 初次使用者：看见原始型号与输入地址时需要翻译技术含义；无设备时，应明确同网条件并让手动连接便于到达。
- 高频办公用户：多文件批次的重复卡片和缺时间的会话列表降低扫描速度。
- 认知负担检查有三项需改善：主要任务焦点、信息分组、渐进展开。五个底部目的地符合 Android 导航惯例，不据此判定选项过载。
- 情绪低点在“找不到设备”和“选择文件后找不到接收人”；接收确认与完成反馈已提供安心感，下一步应让完成后的打开/另存操作更直接。

## 次要细节

- 将页面左右边距统一到 16–20dp 范围，建立分区 20–24dp、行内 8–12dp 的稳定节奏。重复卡片维持现有 8dp 圆角；不用整页大圆角外壳。
- 主操作蓝色、在线/成功绿色、未读与错误红色；活动传输计数用蓝色或进度标记，避免与消息未读混淆。
- 接收提醒继续浮在主体上方，不预留新区域。可用更紧凑的默认形态、查看详情面板与收起入口，降低对上方状态和操作的遮挡。
- 中文界面的分享文字计数应本地化，日常输入不必一直突出 16000 字符上限。
- 夜间模式可作为后续主题项；当前系统深色模式没有对应应用深色方案。应单独设计与核对，而不是简单反色。
- 1.3 倍字号首页尚无裁切，但 Wi-Fi 被拆行，可调整中文换行与“同一无线网络”等文案。保持 48dp 点击范围，避免靠缩小文字和触控面积获得紧凑感。

## 待确认的细化方向

1. 优先范围：先处理首页和聊天（推荐），还是同时统一全部五页？
2. 首页密度：适度紧凑、让设备更靠前（推荐），还是保留较多留白、只压缩已选文件清单？

后续若实施，先处理首页与会话的手机布局，再整理记录和设置的信息层级，最后用 $impeccable polish 统一字阶、状态色与边界状态。
